# Phase 2 compose and mailbox action source review

Date: 2026-11-09

## Scope and method

Read-only source review of draft creation, Gmail Drafts save/readback/delete, send confirmation and uncertain-operation reconciliation, reply/reply-all/forward composition, mailbox actions, mixed-account bulk labels, and frontend error handling. Inspected Java and React/TypeScript source plus the existing relevant test filenames. No application code or tests were changed; no tests/builds were run; no secrets, browser, or Gmail data were accessed.

## Findings

- **Send confirmation and current-content binding:** The backend rejects sends without `confirmed=true`, an `expectedUpdatedAt`, and a review fingerprint (`backend/src/main/java/com/east/app/drafts/DraftService.java:378-392`). Both local and Gmail-saved drafts are read and checked against the timestamp and fingerprint before preparing the Gmail request (`:481-548`). The fingerprint covers mailbox, sender, draft type/source/threading, recipients, subject, both body forms, and attachment names/types/sizes/content digests (`:976-1018`). The UI persists local edits, reads the current draft for review, and exposes a separate “Send this exact message” action (`frontend/src/components/Composer.tsx:797-858,1162-1187`).
- **Uncertain Gmail outcomes:** Save and send are marked pending in independent database transactions before the Gmail side effect (`DraftService.java:445-477,481-559`). If Gmail may have accepted an operation but East cannot confirm it, the draft remains blocked and the UI requires a check of Gmail Drafts/Sent plus a separate attestation before reconciliation (`DraftService.java:583-641`; `frontend/src/components/Composer.tsx:1111-1157`). Sending a saved Gmail draft rereads its current Gmail content and verifies the review fingerprint before `drafts.send` (`DraftService.java:498-525`).
- **Reply and forwarding source scope:** Reply/reply-all/forward creation checks that the source thread belongs to the selected mailbox and app user, and that the source message is part of that thread (`backend/src/main/java/com/east/app/drafts/DraftSourceService.java:71-97`). Reply-all defaults exclude the sending mailbox and addresses already in To (`DraftService.java:1260-1274,1326-1340`). Forwarded files are staged with size/count limits, and the composer tells the user they are included and can be removed (`DraftService.java:138-149,1410-1435`; `frontend/src/components/Composer.tsx:694-723`).
- **Mailbox action ownership:** Every thread action resolves an owned local thread joined through the app user's connected mailbox; user-label IDs are checked against that same mailbox before Gmail is called (`backend/src/main/java/com/east/app/mailactions/MailActionsRepository.java:21-33,61-81`; `MailActionsService.java:148-225`). The UI partitions mixed-account label operations by mailbox, reports per-thread outcomes, and retains failed selections (`frontend/src/components/Conversations.tsx:1464-1515,1516-1553`).
- **No clear source-level bypass found** for explicit sends or cross-mailbox action ownership in the reviewed paths. Source inspection does not prove live behavior.

## Gaps and user-deferred live checks

- At the time of this source review, relevant tests covered draft persistence encryption, Gmail review parsing/snapshot handling, and Gmail send-request shape, but there were no dedicated `MailActionsService` or `DraftService` save/send/reconciliation state-machine tests. Later follow-up added `MailActionsServiceOwnershipTest` (foreign-thread/foreign-label rejection and per-mailbox token selection), `DraftServiceSendSafetyTest` (stale review timestamp and pending-send retry state), and `MailActionsServiceOutboundRoutingTest` (two-mailbox bulk-read outbound request path, bearer-token, label payload, and local-state mapping) plus `DraftServiceReconciliationTest` (confirmed resolution of uncertain local send outcomes). The tests do not yet cover Gmail-backed save/saved-send reconciliation recovery. See the individual focused-test scratchpads for scope and results.
- Live checks still open or deferred: Reply, Reply all, Forward, mixed-account bulk labels, uncertain-operation reconciliation, and other bulk-action outcomes remain unverified. The user explicitly deferred attachment checks, Archive → Move to Inbox, Trash → Restore, Reply, mixed-account bulk labels, and Forward. Do not prompt for deferred checks unless the user reopens them. User-confirmed checks include new draft create/save/readback/send/trash, Star/Unstar, Read/Unread, user-label lifecycle, and Spam/Not spam; those are user reports, not actions performed in this source review.

## Non-blocking label recovery risk

Label creation calls Gmail before inserting the local label mapping (`backend/src/main/java/com/east/app/mailactions/MailActionsService.java:72-97`). If Gmail succeeds and the subsequent local insert fails, East can report a local-sync failure while the remote label exists without its local mapping. Gmail sync upserts label metadata by mailbox and Gmail label ID (`backend/src/main/java/com/east/app/gmail/GmailSyncRepository.java:297-305`), which offers a recovery path, but that failure/recovery path has no dedicated runtime acceptance evidence.
