# Phase 2 sensitive-data boundary acceptance audit

Date: 2026-11-09
Scope: source/docs-only review of the local key, encryption at rest, cache TTL, metadata retention, derived data cleanup, mailbox disconnect, reset, and background behavior. No `.env` or key contents, database rows, browser state, Gmail/API, tests, or builds were accessed.

## Current product decision

The user later removed the startup passphrase and idle lock for this localhost-only application. `AGENTS.md` and the current product/technical/roadmap documents require an automatically loaded owner-only local key file, no routine passphrase prompt or idle lock, and a warned destructive reset if the key is lost. The older passphrase/15-minute-lock wording is superseded. The one-time legacy passphrase migration remains for existing installations only.

## Resolved source finding

The original source audit found that an existing key's parent directory was not repaired/rejected on read and that delete did not reject a symlinked parent. This gap was fixed in the follow-up below. The finding is retained here as audit history; it is no longer an open source issue.

The implemented fix rejects a symlinked or non-directory final parent on read, repairs the POSIX directory mode to owner `rwx` before accessing the key, and rejects a symlinked parent on delete. Existing-key permission repair and parent-symlink rejection have focused synthetic test coverage. The configured user key path and contents were not inspected; non-POSIX ACL behavior remains platform-specific.

## Implementation follow-up — 2026-11-09

- `LocalVaultKeyStore.read()` now rejects a symlink or non-directory at the final parent and reapplies owner-only directory permissions before checking/reading the key. `delete()` rejects a symlinked final parent as well as a symlinked key file.
- `VaultSecurityTest` now covers repair of an existing loose POSIX directory/key and rejection of a symlinked final parent. The targeted class passed: `mvn -o -B -f backend/pom.xml -Dtest=VaultSecurityTest test` (5 tests, 0 failures/errors/skips). Full suite rerun is pending after the sync-state changes finish.
- No key contents or configured local path were read; tests use temporary synthetic key material only.
