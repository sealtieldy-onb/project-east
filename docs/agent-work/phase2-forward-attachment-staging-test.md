# Phase 2 forwarded attachment staging test

Date: 2026-11-09

## Scope

Added a focused case to `DraftSourceCompositionTest` for the Phase 2 rule that forwarding includes source attachments by default and lets the user remove them from the local draft. The fixture supplies an encrypted synthetic source-message cache, synthetic attachment metadata, an owner/mailbox-scoped synthetic token provider, and a fake Gmail HTTP transport returning generated bytes.

The case asserts East requests the attachment for the source message, stages the expected filename/type/size, persists bytes as ciphertext that decrypts only with the draft attachment AAD, and removes the staged file through the local draft delete path.

## Boundaries

- No real Gmail request, mailbox content, credential, browser session, outgoing send, or mailbox mutation was used.
- The fake HTTP client is limited to the single synthetic attachment response; this does not verify Gmail's live attachment behavior or the frontend's forwarded-file review controls.
- The first parent Maven run found that the synthetic repository had inherited `touchLocalDraft`, which attempted to use its absent JDBC connection. Added an owner/draft-scoped in-memory override and assertions for forward staging and removal touches.
- The subsequent parent full suite passed: `DraftSourceCompositionTest` passed all five cases and the backend suite passed 55 tests with 54 passing and 1 opt-in PostgreSQL test skipped.
